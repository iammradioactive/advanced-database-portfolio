# Portfolio 3: Transactions and Concurrency

## Case study
Lagoon Market, using order checkout and warehouse stock allocation.

## Required evidence
The assessment requires transaction examples showing commit, rollback,
isolation, a concurrency issue or control mechanism, and screenshots or
output evidence (MIVA Open University, 2026, p. 3).

## Where to put the work
Keep this activity's files inside this folder. Suggested organisation:

- `scripts/`: executable transaction and concurrency tests.
- `results/`: actual session logs, outcomes and verification queries.
- `screenshots/`: genuine captures where useful.
- `transaction-analysis.md`: explain what each test demonstrates,
  what happened to the data and how the control mechanism works.

Create these subfolders when adding their files. Document the exact steps
for reproducing each multi-session test, including the order of operations.
Do not label expected output as an observed result.

## Implementation and verification
Record the actual database version, commands, isolation configuration,
observed results and limitations after testing.
This structure package does not run transactions or certify their outcomes.
